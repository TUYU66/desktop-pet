## 当前编译范围

工程保留电机与编码器、MPU6050 姿态和平衡控制、OLED、电池电压检测、蜂鸣器/LED、按键和官方手机 App 使用的 UART5 蓝牙协议。默认使用原厂 Normal 模式最终写入的平衡 PID 参数；上电后可按 KEY1 或通过语音起立请求开启平衡控制。

## ESP32 串口最小联调

- J13：STM32 PA2/TX2 → ESP32-S3 GPIO8/RX，PA3/RX2 ← GPIO9/TX，GND → GND，115200、8N1。车板供电时 J13 5V → ESP32 5V；ESP32 暂由电脑 USB 供电看日志时，断开 J13 5V，但仍必须接 GND。只接 TX/RX 没有共地，串口不能可靠通信。
- USART2 接收中断只将字节放入缓冲区；前台处理 ASCII 行协议。STM32 首次完成 ADC 平均后，每约 1 秒主动发送 `BAT,1,<序号>,<电池毫伏>,<平衡已停>,<低电压>\n`。ADC 平均窗约 750 毫秒。ESP32 每 2 秒发 `PING\n`，STM32 回 `PONG,1\n`。可选查询 `STATUS\n` 返回 `STATUS,1,<电池毫伏>,<平衡已停>,<低电压>\n`。倾角仅在 STM32 本地使用，不经串口上报。
- ESP32 收到 `BAT` 后缓存电压；超过 3 秒无新电量帧时将电量置为过期，超过 5 秒无任何帧时判离线。MCP 的 `self.chassis.get_status` 和 `self.dashboard.get_state` 中的 `chassis` 字段提供毫伏、估算百分比、停止与低电压状态。网页设备控制台每秒取一次最新状态。百分比按 3 串锂电的 9.6–12.6 V 区间线性估算，未做电池带载标定，不代表精确续航。
- `STAND,<序号>\n` 尝试启动与 KEY1 相同的原厂平衡控制。车板先检查电池采样是否新鲜和电压是否正常，再开启平衡；运行中的原厂控制中断负责 ±40° 倾角保护，新增看门狗在启动超过 500 毫秒后若 150 毫秒没有姿态更新则停机。这样后靠待机时不会因尚无近期姿态中断而被提前拒绝。`ACK` 只表示请求已接受，不等于已站稳；`ERR` 为 `NOT_READY/LOW_BATT`。
- `REST,<序号>\n` 请求从站立状态轻微后倾后停机。STM32 仅在接近直立（±5°）时接受，后倾目标偏移最多 -2.5°，最长 450 毫秒，休息期间不叠加速度环与转向环输出，PWM 限制在 ±1600；连续 3 次姿态采样均达到约 -1.2° 且比起始角向后变化至少 0.4° 后立即断开电机，让后支架接住。超时、方向不对、轮速过大或低电压时取消休息并保持平衡。串口异步发送 `REST_DONE`、`REST_ABORT` 或 `REST_FAULT` 供 ESP32 日志区分结果。`ERR` 可能为 `NOT_READY/LOW_BATT/ANGLE/NOT_STANDING/FAULT`。`ACK` 仅代表动作启动，支架是否接住必须实机确认。`STAND` 可从休息状态重新启动原厂平衡控制。
- `TURN,L/R/B,<序号>\n` 由 STM32 执行完整动作。已站立时先连续确认倾角、轮速与角速度稳定，转向后再次确认，最后保持站立；坐下时必须先检测持续静止的后倾姿态，再复用 `STAND` 的启动路径，站稳后转向、再次站稳，最后缓慢后靠，确认静止的后倾姿态才发 `TURN_DONE,<序号>`。仅凭电机停止标志不会自动起立。站立入口允许正常平衡修正造成的瞬时 ±18° 倾角；真正起转前与转完后，要在连续采样窗口中限制倾角、角速度和轮速，并限制前后净位移，然后等到倾角回到 ±5°。`ACK` 只表示接收；途中异常发送 `TURN_ABORT,<序号>,<原因>`。转角使用有符号的陀螺仪积分，反向摆动会抵消进度；反向累计达到 15° 会提前中止。`TURN_RIGHT_GYRO_SIGN` 按当前 MPU 面朝上安装设为 -1，首次实测若报 `WRONG_DIRECTION`，先确认实际转向和安装方向，再调整符号，不要连续重试。
- ESP32 的 MCP 工具 `self.chassis.get_battery`、`self.chassis.stand_up`、`self.chassis.rest` 分别用于语音查询电量、起立、休息。语音回答注明百分比是粗略估算。
- 语音动作按“模型识别身体动作意图 → 播报简短回复 → 服务端发设备 MCP → ESP32 等本地解码与播放完成（最多 3 秒）→ UART 发 `STAND/REST`”执行。坐下、躺下、靠回支架等表达对应休息意图。若播报被打断、没有送出音频或设备播放超时，本轮动作取消。设备拒绝或后靠中止会写入日志；动作回复本身先于硬件执行，不能当作执行完成证明。
- 动作请求不再被 ESP32 缓存的连接状态或电量状态提前拦截：ESP32 发送带 1～65535 循环序号的 `STAND/REST`，STM32 根据当下采样和安全条件决定 `ACK/ERR`。ESP32 仅由后台串口任务接收并解析所有帧，动作调用等待匹配序号的回执；未收到回执时按“结果未知”处理，不自动重发。日志中的 `TX STAND request` 表示 ESP32 已写入串口；`STM32 request ... rejected` 表示 STM32 明确拒绝；超时则需检查供电、共地、接线及车板程序。

## 后续接入边界

- 现有上电/按键和平衡控制沿用官方 Normal 模式。语音休息期间及休息完成后，屏蔽原厂的放下自动恢复，以免停机后自行重新启动。新的轻微后倾参数尚未根据实测支架角度校准；若方向不对、未后倾或未到支架，必须调整后再正常使用。蓝牙控制权切换仍属后续阶段。
- 蓝牙 App 上报包保留超声波距离字段，因未安装该模块固定填 0；电池电压、速度等字段仍由现有采样和编码器提供。
- 原厂低电压停机阈值仍为 9.6 V。12.6 V 电池的电量百分比需要依据实测带载电压另行标定；当前显示“约”。
- 扩展 `MOVE` 等运动协议前，STM32 应保存最近的命令序号及其回执，收到重复命令时只重发回执，避免 ACK 丢失后的重试造成重复运动；当前命令行缓冲区为 64 字节。`ACK` 只表示已接受，转向结果以 `TURN_DONE/TURN_ABORT` 为准。

用户已实测单独语音起立成功。本次完整转向状态机尚未烧录和实机验证；先在开阔平地、有人扶持且可立即操作实体电源开关时，分别验证坐下起立、站立转向、坐下转向，观察 `TURN_DONE/TURN_ABORT` 和最终支架状态。若方向错误、刚起立就倒、IMU 超时或未坐稳，立即停止测试并反馈日志，不要连续重试。ESP32 用电脑 USB 时保留 J13 GND/TX/RX，断开 J13 5V。
