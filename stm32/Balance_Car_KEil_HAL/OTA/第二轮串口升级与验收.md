## 接线与实际升级步骤

1. 先让底盘坐下，车体稳定支撑。
2. 使用 3.3 V 电平 USB-UART：适配器 TX → STM32 PA3/RX，RX → PA2/TX，GND 共地。
   不连接适配器 VCC。先断开 ESP32 与 STM32 这条串口的 TX/RX，避免两个发送端驱动同一 RX。
   本轮协议在 USART2，不默认底盘自带的 USB 串口就是此接口。
3. 确认 Python 环境有 `pyserial`，从工作区根目录执行（COM 号替换成实际值）：

```powershell
& 'D:\miniconda3\envs\xiaozhi\python.exe' stm32/Balance_Car_KEil_HAL/OTA/tools/serial_update.py tmp/stm32-ota-stage2-20261104/application-test-v2026110402.zip --port COM7
```

4. 出现 `Port open...reset STM32` 后，在 40 秒内按 STM32 复位键。
5. 观察传输字节进度。发送端验证每包确认的偏移，发送完整镜像校验和安装请求。
6. 显示 `Installation verified; reboot requested` 代表 Bootloader 已确认安装并接收复位请求；
   还需观察 OLED/恢复 ESP32 串口后的底盘遥测，确认应用确实启动。
7. 断开 USB-UART 的信号线，再恢复 ESP32 串口，回归站立、坐下和 BLE 功能。

候选固件版本必须大于已安装包版本，不能反复使用同一版本测试。
本轮测试包只有包版本变化，应用业务代码相同；现有 `DIAG,FW` 常量不会随包版本变化，
Bootloader 的 HELLO/安装响应使用 Journal 中的版本。后续桥接会统一对外展示升级版本。

如果没有能直连 PA2/PA3 的 USB-UART，可先完成动作修复与整包启动验证，再接入 ESP32 桥接后
做升级验收；不要把 App BLE 连接当作本轮串口升级入口。

## 串口协议 v1

115200、8N1，帧为 `@payload*HHHH\n`；CRC16/CCITT-FALSE 覆盖 payload，
初值 FFFF，多项式 1021，`123456789` → `29B1`。CRC 必须为四位大写十六进制。
帧最多 640 字节；遇 `@` 重新同步，超长/CRC 错误/串口 ORE 等丢弃当前帧。
载荷全部 ASCII，数字无符号十进制；DATA 的二进制载荷使用十六进制文本。

| 请求 payload | 含义 |
| --- | --- |
| `OTA,1,session,seq,HELLO` | 建立会话并查询状态/当前版本 |
| `OTA,1,session,seq,BEGIN,YB-EST01-V2.0,version,size,crc32,134250496` | 检查版本、板型、固定装载地址，提交接收状态并擦暂存区 |
| `OTA,1,session,seq,DATA,offset,HEX` | 最多 256 字节，偏移与长度必须半字对齐且顺序接收 |
| `OTA,1,session,seq,END` | 校验完整暂存镜像及启动向量，提交 READY |
| `OTA,1,session,seq,INSTALL` | 先提交 INSTALLING，再逐页复制并校验应用，提交 INSTALLED |
| `OTA,1,session,seq,RESET` | 只允许在已安装且应用校验通过时复位 |

成功响应：`OTA,1,session,seq,OK,received,state,currentVersion`。
失败响应：`OTA,1,session,seq,ERR,code`，code 为 COMMAND/BEGIN/DATA/IMAGE/INSTALL/RESET。
状态值：1 INSTALLED、2 RECEIVING、3 READY、4 INSTALLING。
session/seq 为非零 uint32，seq 严格递增；最近一包完全相同的重发重放原响应，不重复写入。
相同序号改内容、旧序号、非当前会话不执行。新会话需要重新 BEGIN，不跨复位续传接收偏移。
发送端超时会重发原帧；不会因超时换一个序号盲目重复安装。

## 断电行为与日志

- 接收中断电：应用区未擦，旧应用有效时可正常启动；下一次重发完整包。
- READY 后断电：旧应用仍有效，未经 INSTALL 不自动覆盖。
- 安装中断电：复位发现 INSTALLING，先校验完整暂存镜像，再从第 0 页重新复制。
- 新应用安装日志提交中断电：旧 INSTALLING 日志仍在，复位后可再次完整安装。
- 暂存镜像损坏：拒绝跳转，但允许重新 BEGIN 完整传包。两份日志均无效仍须 SWD 整包恢复。
- 正常启动等 500ms 握手；已建立会话 30 秒无有效请求时，旧应用仍校验有效且未进入 INSTALLING 才启动。

日志为 `BOOT,2,START`、`BOOT,2,RESUMING_INSTALL`、`BOOT,2,INSTALL_FAILED`、
`BOOT,2,APP_VALID`、`BOOT,2,FLASH_SIZE_ERROR`。当前 ESP32 常规协议不会显示 BOOT 原始文本。
