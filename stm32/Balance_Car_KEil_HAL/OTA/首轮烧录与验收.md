## 首次安装操作

1. 使用现有 ST-Link/SWD 接线连接底盘，保持 BOOT0 为正常 Flash 启动配置。
   将车体放稳或支撑好，先验证开机保持坐下/停止状态。
2. 用 STM32CubeProgrammer 或已使用的 ST-Link 烧录工具打开 `factory-stage1.hex`。
   HEX 自带地址，不要设置整体偏移，不要把整个文件当 BIN 写到单一地址。
3. 执行下载并勾选写后校验；本轮不需要改读保护、写保护或 BOOT 选项。
4. 下载完成后复位运行。工具若保持 CPU 停止，断开调试并复位后观察。
5. 正常时应进入原先底盘应用；网页显示底盘连接，ESP32 恢复接收原有 DIAG/电量/姿态日志。

使用独立程序员烧录整包，避免直接点击普通 Keil 工程的 Download 覆盖 Bootloader。
恢复普通版时，烧 `normal-recovery.hex` 即回到原来的启动入口；之后要恢复 OTA 启动，
再次烧最新的 `factory-stage1.hex`。

## 验收顺序

1. **启动与静止**：冷开机和复位各验证数次，无异常自启电机；底盘正常上线。
2. **FreeRTOS 与中断**：检查 DIAG,RTOS / TASKS / IRQ / QUEUE；堆栈没有持续下降，
   控制中断持续运行，没有新增队列满或 TX 超时。记录一次实际数值。
3. **普通动作**：站立、重复站立、坐下、转身；确认姿态和动作回执正常。
4. **BLE**：语音开启控制、App 连接、移动/松手停止、退出、断连停车。
5. **失效镜像（后续有恢复条件时做）**：擦除出厂记录页或破坏应用后复位，
   Bootloader 应保持静止且拒绝跳转；测试后重烧整包恢复。

Bootloader USART2 日志为 115200、8N1，启动阶段使用 HSI 8 MHz，进入应用后恢复其正常时钟。
原始输出可能是：

```text
BOOT,1,START
BOOT,1,APP_VALID
```

错误分别为 `FLASH_SIZE_ERROR`（芯片容量不匹配）、`INVALID_RECORD`（出厂记录无效）、
`INVALID_IMAGE`（应用校验失败）。当前 ESP32 的常规遥测解析器不展示 BOOT 原始日志，
看不到这两行不代表没经过 Bootloader；成功后原有底盘遥测正常即是首先观察的证据。
需要直接抓日志时监听 STM32 PA2/TX，并避免两个 TX 同时驱动 STM32 的 PA3/RX。

## 已实现的启动保护及限制

- `SystemInit` 在 C 运行库初始化前将 PC6–PC9 配置为低电平输出，不启动 TIM8 PWM。
  这些脚对应当前四路电机 PWM；其物理安全行为仍以本机驱动实测为准。
- 实际 Flash 容量必须为 256 KiB；出厂记录、应用向量和全镜像 CRC 全部通过才跳转。
- 跳转前关闭并复位启动串口，关闭 SysTick，清理 NVIC pending/enable 和 PendSV/SysTick pending，
  设置 VTOR，再用汇编设置 MSP 和复位入口；更换栈后不再执行 C 栈操作。
- 偏移应用的 `SystemInit` 根据链接符号设置 VTOR，避免中断仍跳到 Bootloader 向量表。
- Bootloader 本轮不会擦写 Flash，失效状态只能通过 SWD 恢复；下一轮才加入串口接收和安装。
- SHA256/CRC 用于完整性，不是签名认证；远程升级鉴权与受信任发布验证将在桥接阶段接入。

本轮编译和主机测试通过后，仍需上面的实机验证才能确认启动链路在本机可用。
