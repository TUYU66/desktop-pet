# 网页自定义唤醒词

## 首次启用

1. 在运行 Python 服务的环境中安装新依赖：`python -m pip install pypinyin==0.55.0`。
2. 重新构建并重启 Java 服务，重启 Python 服务。前端开发服务会加载修改；生产部署需更新前端构建。
3. 在 ESP-IDF 终端进入固件目录，由你编译并完整烧录：

```powershell
idf.py -B build-v2 build
idf.py -B build-v2 flash monitor
```

需要完整 `flash`，让 `mn6_cn`、`fst` 和原 WakeNet 模型一起写入资源分区。
不要使用只烧应用的 `app-flash`。不用擦除 NVS，不改固件版本号。

## 使用

网页“设置 → 叫醒小智”输入一个 3～8 字的中文唤醒词，点击“保存唤醒词”。
不支持空格、数字、标点或中英混写。读音自动转为无声调拼音；多音字采用词典读音，
如果某个名字效果不佳，可以换一个读音明确的词。

- “已保存，正在等待设备确认”：后台已保存，不能据此认为设备已经换词。
- “设备已生效”：设备确认模型配置成功，且 NVS 持久化提交成功。
- “等待设备上线”：设备重连后自动补发；通常等待 5～10 秒，初始化时可能更久。
- “固件暂不支持”：烧录本次固件。
- “尚未应用成功”：查看串口日志和后端状态；仍可使用“你好小智”。

清空输入并保存会关闭自定义唤醒词。“你好小智”始终保留。
修改机器人名字、角色或声音不会改动独立保存的自定义词。
初版沿用本项目单设备模式；有多台设备在线时暂停下发。

## 本次与实验版的差别

取消了每 90 秒自动换词。自定义词现在会真正触发对话，走原有唤醒回调。
仍使用实测时的 70% 识别阈值，未修改长期记忆 Prompt。
模型识别和换词由同一把锁保护；设备在确认持久化成功后才回复成功。
旧请求、错误词的确认不会被当作当前设置已生效。
服务每轮读取数据库中的最新设置，离线、丢失通知或重启后自动重试。
重启设备时先读取本地 NVS；联网后再与网页保存的值同步。

串口关注 `DynamicWakeWord`：`Ready` 表示模型就绪，`Applied and saved`
表示新词已应用并保存。没有保存自定义词时，仅“你好小智”生效。

## 验收

1. 保存新词，等网页“设备已生效”，验证新词和“你好小智”均能开始对话。
2. 换另一个词，确认旧自定义词不再触发，新词有效。
3. 重启硬件，再验证当前词。
4. 设备离线时保存，连接后确认自动生效。
5. 清空保存，验证只有备用唤醒词生效。
6. 对话或播放中修改，然后回待机测试；继续观察日常环境的误唤醒。
