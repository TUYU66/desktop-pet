# 长期记忆后台队列与缓存

## 生效方式

重新构建并重启 Java 服务，重启 Python 服务。此次不需要更新 ESP32 固件或前端。
Java 新增只读的 `/memories/semantic/revision` 接口，无数据库结构变更。
旧 Java 服务没有此接口时，Python 会回退到完整快照读取，功能可用但缓存刷新更慢。

## 普通聊天

收到真实用户消息后，固定消息 ID、角色、会话、原文和发生时间，先写入本地待办库，
随后开始聊天模型回复。V2 写入由后台 Worker 执行；不再等待记忆模型或数据库 Commit。
回复失败、断开设备连接不会撤销已经入队的任务。

任务按实际记忆 API 的服务地址、身份和角色隔离；同一个归属跨 WebSocket 连接串行，
不同归属可以并行。当前部署只允许一个 Python 进程拥有同一个待办库，
第二个进程会拒绝接管，避免偷偷并发写入。

待办库默认位置：`xiaozhi-python-server/data/memory-outbox.sqlite3`。
可用 `XIAOZHI_MEMORY_OUTBOX` 指定路径。不要删除这个文件来处理故障。
它包含尚未完成的消息和提交提案，不保存模型 API Key。

进程重启后，相应角色连接初始化时恢复其待办；未再次启用的角色继续保留在库中等待。
每个归属最多积压 256 项；满队列时记录 `queue_full`，不声称保存成功。
最多保留约 1024 项近期完成记录用于去重，未确认提交不会被清理。

## 显式记忆请求

“记住”“帮我记一下”“忘掉”等表达用于路由到等待确认路径，不替代 V2 的语义判断。
这类请求也进入同一队列，不越过旧任务。最多等待 12 秒，只有取得确定 Commit
结果才反馈新增/修改/作废数量；超时后后台继续，回复只能说明尚未确认。
纯粹列出已保存记忆的请求只读取，不进入写入模型。

普通消息不主动报告后台保存过程，不声称已经保存。严格整句匹配的寒暄和致谢会跳过
写入，例如“谢谢！”；含其他内容的复合句不会跳过。“继续”也保留给模型处理。
这次没有改长期记忆 Prompt、Retriever/Decision/Validator/Commit 的语义职责。

## 读取缓存

连接初始化预热快照。普通聊天读取复用相同归属的缓存，每隔最多 2 秒以轻量 revision
查询检查变化。版本不变不重新拉全量快照；版本变化清理快照和历史缓存。
写入成功、版本冲突或提交结果未知时，本进程主动使缓存失效。

网页手动编辑/删除通过数据库 revision 在下一次检查被发现，普通聊天允许至多约 2 秒
的缓存陈旧窗口。明确列出记忆时强制进行版本检查，不使用此窗口。
按每轮问题重新检索缓存中的记录，不复用上一轮问题的召回文本。
历史读取最多 4 路并发，并按 revision 缓存。读取整体超时为 3 秒，失败时不编造记忆。
写入决策仍读取真实数据库快照，绝不使用聊天缓存来选择更新目标或提交版本。

## 失败和恢复

- `rejected` / `uncertain` / `conflict`：确定性结果，不重抽模型答案。
- 临时失败：最多尝试 3 次，重试间隔 1 秒、3 秒，同一队列后面的任务等待。
- Commit 结果未知：先持久化的原提案、turnId、版本原样重发，不重新运行模型。
- 未确认 Commit 用完重试次数：标记 `blocked`，暂停该归属后续写入，其他角色继续。
- 提交前失败用完次数：标记 `failed`，保留失败记录，后续任务继续。

查看待办状态（不输出消息原文）：

```powershell
python scripts/memory_queue.py status
```

发现 `queue_blocked` 后先检查 Java/网络是否恢复，再停止 Python 服务，重新安排同一原始
Commit 重试（`123` 替换为日志中的 jobId），然后启动 Python 并连接对应角色：

```powershell
python scripts/memory_queue.py retry-blocked --id 123
```

此工具不允许重试 Validator 拒绝的提案，也不会修改原始提交内容。

## 验证与耗时

测试覆盖队列顺序、跨归属并行、进程锁、上限、重启恢复、原提案恢复、确定性拒绝不重试、
普通聊天到达主模型时记忆仍在后台执行、显式等待、缓存版本和历史缓存等。
49 项 Python 回归测试通过。未进行真实模型速度对照；没有声称固定减少多少秒。

运行日志可对照：

- `chat_timing memory_prepare_ms`：进入聊天到读取/入队准备结束的耗时。
- `chat_timing first_llm_chunk_ms`：进入聊天到主模型首个输出片段的耗时，不等于扬声器首声。
- `queued / queue_result / retry_scheduled / queue_blocked`：后台任务进展。
