# 热点与备用Web Search：收缩后的职责

## 唯一路由原则

- 普通知识、梗含义、人物、游戏知识和常见事件背景：聊天LLM优先使用已有知识和当前上下文回答。对新近细节或没有把握的内容说明不确定，不冒充已核实信息。
- 当前平台热榜：get_news_from_newsnow读取NewsNow，主聊天LLM整理、解释、继续聊天。
- 用户明确要求查/搜/核实，或在询问后明确同意：独立web_search执行一次Tavily公开网页搜索。
- Platform Search（真正的平台站内关键词搜索）：尚未实现，Tavily不模拟这个能力。

不因“最近”“怎么回事”“热梗”等词强制搜索。“讲讲第二个”优先复用已有上下文，不自动再次联网。知识是否可靠和时效是否足够仍由主模型判断，未知不等于工具自动运行。

## NewsNow工具

工具名保持get_news_from_newsnow，只接受：

| 参数 | 意义 |
| --- | --- |
| category | general/community/entertainment/news/tech，默认general |
| sources | 用户要看的平台，最多四个，省略使用类别默认来源 |
| count | 返回1～5条，默认3 |

不再有intent、topic_discover、detail、query、item_index或自动fallback。也不再通过额外一次LLM调用筛选候选；NewsNow返回榜单后直接交主模型整理。旧参数返回说明，不触发其他服务。
平台部分失败保留其他已选平台的可用结果；全部失败说明榜单未取到。空榜不证明某圈子没有讨论。不进行Tavily降级。
保留5分钟默认HTTP缓存（最多10分钟、64组），榜单标有来源及编号，当前对话工具结果用于后续复用。
旧的GDELT地区报道路线已从热点工具移除；明确请求联网查地区新闻可使用独立web_search。

## 独立Web Search

工具名web_search，只接受完整query，最多500字。它提供公开Web结果，不承诺能搜索到抖音、B站、微博、贴吧的站内全部内容，也不提供平台热度证明。

授权检查基于连接中真实用户消息，不接受模型传入confirmed=true代替授权：

1. 常见明确查证请求可以执行。
2. 用户简短肯定回复，且紧邻的上一轮助手确实询问是否联网查询，可以执行。
3. 如果工具被误调用但用户未授权，只返回“要我帮你联网查询一下吗？”，不发网络请求。确认后绑定此前待查询问题。
4. 授权确认窗口5分钟，待确认请求绑定当前会话；同一真实用户轮最多一次搜索。重复调用复用本轮结果，不重复请求或自动重试。
5. 授权检查采用保守的常用表达识别。复杂、含糊或否定表达可能再次询问，不猜测同意；没有新增授权分类模型。

Tavily成功返回资料后交LLM整理，并区分搜索摘要与已知背景。连接失败直接说明请求未完成，不能说“搜了一圈没有结果”。empty表示没有可用搜索资料，不表示事件不存在。用户切换问题后迟到结果不使用。

## 配置与迁移

原get_news_from_newsnow.url继续指向已部署的本地NewsNow；平台及缓存配置不变。web_search已加入默认Intent.function_call.functions列表，重启Python重新加载工具。

Tavily配置可以放到独立插件：

```yaml
plugins:
  web_search:
    search_api_key: "填写自己的Key"
    search_transport: auto
    search_timeout: 24
    search_connect_timeout: 6
```

TAVILY_API_KEY环境变量优先。为避免要求重新填写已有密钥，新工具仍可读取原get_news_from_newsnow下的search_api_key/search_transport作为迁移默认值；独立web_search配置优先覆盖。热点流程不再读取或使用搜索凭据。

Windows的auto通道使用此前验收过的系统curl.exe，其他系统用HTTPX。保留证书校验，Key与正文通过标准输入，不写入命令行、日志或临时文件；请求不自动重试。可以显式设curl或httpx。默认网络预算24秒、连接阶段6秒；可分别配置search_timeout（8至24秒）和search_connect_timeout（1至8秒且不超过总预算）。curl进程等待比网络预算多2秒；超时或取消会终止子进程并回收管道。HTTPX也受独立的总时限约束。

2026-09-30截图中的18秒超时没有HTTP状态，无法据此判断密钥失效。新日志中connect_timeout表示TLS连接未完成，timeout表示等待返回或总期限到达；401/403/429才提示检查密钥或额度。仅记录代理环境变量是否存在，不显示其值。本次修改没有执行真实联网验证，扩大超时预算不等于解决网络或代理故障。阶段划分依据[curl time_appconnect说明](https://curl.se/docs/manpage.html#time_appconnect)。

日志：
- NewsNow 看榜开始/完成/失败：只有榜单请求。
- Web Search 等待用户确认：没有请求Tavily。
- Web Search 已授权：标注explicit_request或confirmation。
- Tavily 请求通道/搜索开始/完成/失败：只在授权后的独立搜索发生。

## 代码结构

- plugins_func/functions/get_news_from_newsnow.py：纯榜单工具入口与回复说明。
- core/news/protocol.py、catalog.py、pipeline.py、providers.py：榜单参数、平台、取榜流程和HTTP适配。
- plugins_func/functions/web_search.py：独立备用联网工具入口。
- core/web_search/service.py：授权与单轮请求边界。
- core/web_search/provider.py、transport.py：Tavily请求及curl/HTTPX通道。

长期记忆提示词和流程未修改，聊天人格提示词未修改。主聊天模型通过新的工具描述了解职责边界。

## 用户自行验证

本次不运行编译、自动测试或付费搜索，仅做静态检查。重启Python后检查：

1. 问常见梗含义、游戏知识：模型直接回答，不应该出现Tavily日志。
2. 问当前平台榜单：只出现NewsNow请求，正常播报编号。
3. 追问第二个：优先上下文回答；不自动搜索。
4. 明确“帮我查一下某件事”：web_search显示已授权，再调用Tavily。
5. 模型询问是否查询，用户说“好”：查询；用户说“不用查”：不能查询。
6. 误调用web_search、未获授权：只问确认，不消耗搜索额度。
7. 同轮重复调用、请求失败：不重试、不转换为其他搜索路线。

实际是否恰当使用已有知识、主动承认不确定，仍需要对聊天模型的真实回复进行验收。
