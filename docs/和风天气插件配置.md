# 和风天气插件配置

编辑 `xiaozhi-python-server/config.yaml` 中的 `plugins.get_weather`，填好后重启 Python 服务。无需编译 ESP32 或 Java。
如 `data/.config.yaml` 中存在同名字段，它会覆盖 config.yaml。

```yaml
plugins:
  get_weather:
    api_host: "你的专属域名.qweatherapi.com"
    api_key: "天气预报项目的 API KEY"
    geo_api_host: ""  # 同一 Host 留空；不同账户时填 GeoAPI Host
    geo_api_key: ""   # 共用凭据留空；独立项目则填 GeoAPI 的 API KEY
    default_location: "广州"
    forecast_api: "v1"
    forecast_days: 7
    cache_seconds: 600
```

- API Host：和风控制台“设置”中查看。填域名，不填接口 URL。
- API KEY：项目中创建的 API KEY 凭据，不是项目 ID、Key ID 或 JWT 私钥。
- 同一凭据获准访问两类 API 时，GeoAPI 两项留空即可复用；分别申请的凭据则分别填入。
- 新版逐日预报 `/weather/v1/daily/{latitude}/{longitude}` 使用 `forecast_api: v1`，天数 1～10。
- 如果开通的是 `/v7/weather/7d` 等城市逐日预报，使用 `forecast_api: v7`，天数可选 3、7、10、15、30，具体权限以账户为准。不会在接口失败时自动请求另一版。
- 地理查询为 `/geo/v2/city/lookup`。地名先解析为城市，再请求预报。未指定城市时使用 default_location。
- 默认返回七天预报，包含当地日期、昼夜天气和最低/最高温度；不调用实时天气 API，也不把当日预报表述为实时观测。
- 成功数据缓存十分钟，失败不写入天气成功缓存。Host/Key/语言/城市/预报版本改变会使用不同缓存键。启动时已有天气背景加载机制仍保留。
- 同名地点默认采用和风排序第一项，结果包含行政区；可提供更完整地名区分。
- 请求使用 HTTPS 和 X-QW-Api-Key 请求头，日志不输出密钥或完整上游异常。

## 验证

填好后重启 Python，询问默认城市天气、指定城市明天天气和未来几天天气。
检查返回城市、日期与控制台接口是否一致。未开通实时接口时，不应期待实时气温。
本次已通过九项模拟接口测试，尚未使用实际凭据验证服务权限、额度及真实返回。
